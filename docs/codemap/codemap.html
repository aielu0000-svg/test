Destructive concurrency guard

web/src/server/destructiveConcurrency.ts is registered by routes/features.ts. For test cases, folders, scenarios, data sets, runs, evidence and procedures, DELETE/restore now:

  1. requires an authenticated user with project edit permission;
  2. requires body projectId and the client-observed version;
  3. locks the target row with SELECT … FOR UPDATE inside the request transaction;
  4. returns HTTP 409 on stale version or wrong deleted/active state;
  5. holds the row lock through the route mutation and request commit/rollback.

Concurrency regression

  • Two sessions for the same administrator observe the same folder version and issue simultaneous PATCH requests: one succeeds and one returns 409.
  • An assigned executor and administrator update independent rows concurrently: both succeed.
  • After another session advances a row version, a stale DELETE returns 409 and leaves the row active.
  • After fresh DELETE and one successful restore, a second stale restore returns 409.
  • Logging out one same-user session leaves the other same-user session and the different-user session authenticated.

API contract

web/openapi.yaml is now a mapped contract boundary. Versioned destructive mutations require projectId + version and document HTTP 409. DB schema and migrations are unchanged.
