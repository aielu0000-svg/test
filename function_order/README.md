# 手順書 Markdown 取込機能メモ

最終更新: 2026-04-23

## 背景

既存プロジェクト `/home/ser/dev/the-test` に最終統合する新機能として、Markdown で作成した手順書を読み込み、手順実施用の画面へ変換する。

従来は Excel で手順書を作成していたが、Excel 作成・整形に工数がかかるため Markdown 化したい。一方で Markdown だけでは Excel のような数式・自動計算ができず、開始時刻・終了時刻から所要時間を計算する用途に弱い。そのため、Markdown を入力ソースにしつつ、アプリ側で予定日時・実施日時・所要時間を扱える機能を作る。

## draw.io から読み取れたドラフト

画面案は大きく 3 状態。

1. 画面1: 手順一覧
   - タイトル例: `テスト1`
   - 手順カード/行: `手順1` から `手順6`
   - 予定日時の表を持つ
   - 列: 開始、終了、所要時間（分）

2. 画面2: 手順詳細
   - 手順を押すと詳細表示へ遷移
   - Markdown の見出し・本文・コードスニペットを表示
   - コードスニペットは枠内表示
   - コピー機能を付ける
   - 枠外を押すと一覧へ戻る想定

3. 画面3: 実施日時入力
   - 選択ボタン押下またはスライド操作で、予定日時から実施日時表示へ切り替える想定
   - 実施日時の開始・終了から所要時間を自動計算する

Markdown 変換ルール。

- `#` は `##` をまとめる大グループ
- `##` は手順グループ
- `###` は実作業手順
- `##` の下に `###` が複数ある場合、アプリ側で `1.`, `2.` のように自動採番する
- コードブロックは枠内に表示し、コピーできるようにする

draw.io 内のサンプル Markdown。

~~~md
## 事前準備

### namespace作成

```
oc new-project dbproxy-ci
```

### イメージ作成

---

haproxyのイメージを作成する

```bash
oc -n dbproxy-ci import-image haproxy:3.3.6 \
  --from=docker.io/library/haproxy:3.3.6 \
  --confirm
```
~~~

## 暫定機能案

### Markdown 取込

- ローカルの `.md` ファイルを選択して取り込む
- 取り込んだ Markdown から手順書タイトル、手順グループ、個別手順、本文、コードブロックを解析する
- 解析結果をアプリ内データとして保持する
- 取り込み後にプレビューし、見出し階層の解釈を確認できるようにする

### 手順一覧

- 左または中央に手順一覧を表示する
- 各手順に予定開始、予定終了、予定所要時間を表示する
- 予定所要時間は `HH:mm` 形式で入力し、最初の予定開始時刻または途中で変更した日時から予定開始・予定終了を自動計算する
- 手順を選択するとポップアップで Markdown 内容を表示する
- 画面遷移を減らし、一覧を見ながら詳細確認できる構成にする

### 実施記録

- 予定日時とは別に実施開始、実施終了、実績所要時間を持つ
- 実績所要時間は実施開始・実施終了から自動計算する
- 予定と実績の差分を表示するかは未決
- 実施開始・終了は手入力に加えて、現在時刻を入れるボタンがあると運用しやすい
- 予定日時・実施日時はいずれも Markdown には書かず、アプリ側で入力する

### 予定日時作成フロー

- 先に保全で手順を実施し、各手順にかかった時間を確認する
- 予定日時側では、各手順の「かかった時間」を入力する
- 最初の予定開始時刻を入力すると、各手順のかかった時間を順番に積み上げて予定開始・予定終了を自動作成する
- 最初の予定開始時刻を変更するだけで、本番用の予定日時へ全体を再計算できるようにする
- 自動作成された予定日時は、あとから手順ごとに手動調整できるようにする
- 途中の手順で日時を変更した場合、その手順以降は変更後の日時を起点に、各手順のかかった時間を積み上げて再計算する
- 途中日時の変更は、その変更位置より前の手順には影響させない
- 手順単位の手動調整は、その行を新しい起点として扱い、後続手順を積み上げ直す

### 実施日時作成フロー

- 本番実施時は、実施開始打刻と実施終了打刻を行う
- 実施開始・終了から実績所要時間を自動計算する
- 実施日時は打刻中心だが、誤打刻や後追い入力に備えて手動修正もできるようにする

### コードブロック

- Markdown のコードブロックを手順詳細内で枠表示する
- 各コードブロックにコピー操作を付ける
- 言語指定がある場合はラベル表示する

## UI 方針

既存アプリは Electron/Vite/React/Tailwind 構成。運用ツール寄りの画面なので、派手なランディングではなく、作業中に迷わない密度の高い UI にする。

- 画面上部: Markdown 取込、保存、予定/実施の切替、状態フィルタ
- メイン: 手順一覧を中心に表示する
- 手順詳細: 行クリックでポップアップ表示する
- ポップアップ内: 手順本文、コードブロック、コピー操作
- 一覧列: 開始、終了、所要時間を表示する
- 予定日時と実施日時は draw.io の画面3イメージを参考に切替表示する
- 切替後も列構成は変えず、見出しと入力値だけを「予定日時」「実施日時」で切り替える
- 作業中は「今開始」「今終了」ボタンで時刻入力できるようにする
- 画面はできるだけ見やすく簡潔にする。詳細を常時表示する分割ペインは避け、必要な時だけポップアップで開く。

## 決定事項

- `#` は `##` をまとめるグループとして扱う
- `##` は手順グループ、`###` は実作業手順として扱う
- 予定日時・実施日時は Markdown に書かず、アプリ側で入力する
- 手順詳細は画面遷移ではなくポップアップで表示する
- 日時は内部的に `YYYY-MM-DD HH:mm` として扱い、画面表示では `4/16 12:00` のような短縮表示にしてよい
- 一覧の予定列・実施列は同時表示せず、切替ボタンで表示する
- 予定日時は、最初の予定開始時刻または途中で変更した日時と、各手順の所要時間をもとに自動作成する
- 予定日時は自動作成後に手順単位で手動調整でき、調整した行以降はその日時から所要時間を積み上げ直す
- 実施日時は開始打刻・終了打刻で入力する
- データ保存は SQLite を使う
- 既存サイドメニューには追加せず、完全に別の新しいメニューとして切る
- Markdown を再読み込みしても、入力済みの予定日時・実施日時などは保持したい
- 手順追加や順番変更を考慮し、Markdown 再読み込み時は手順の同一性判定が必要
- 予定所要時間は `HH:mm` 形式で入力できるようにする
- 実施の開始・終了ボタンは詳細ポップアップ内に置く
- 画面1の日時表示部分をクリックすると日時修正できるようにする
- 検索機能は設けない
- 補足欄は設けない
- 基準日時は、最初の予定開始時刻および途中で変更した日時そのものを基準として扱うため、独立した基準日時入力欄は設けない
- 詳細ポップアップの作業表示は Red Hat Docs のように、番号付き手順、本文、コードスニペット、コピー操作が読みやすいドキュメント形式に寄せる
- 詳細ポップアップには見出しジャンプ用のサイドメニューを置かない
- コードコピーは文字なしのアイコンボタンにする
- Markdown のコードスニペット言語指定に応じて、`bash` / `yaml` などの表示色を変える
- Red Hat Docs のライト/ダーク配色を参考に、ダークモードを用意する

## Markdown への反映について

アプリ側で変更した内容を Markdown ファイルへ反映することは技術的には可能。ただし、何を Markdown に戻すかは分けて考える。

- 手順本文、見出し、コードブロックなど Markdown 由来の内容は Markdown に反映しやすい
- 予定日時、実施日時、打刻、所要時間、手動調整情報は運用記録なので SQLite に保存する方が自然
- Markdown へ実績情報を書き戻す場合は、コメント、専用テーブル、front matter などの専用記法を決める必要がある
- 現時点の第一候補は、Markdown は手順定義、SQLite は予定・実績・調整履歴として分離する方式
- 実績情報を Markdown に戻すかどうかは検討項目として残す
