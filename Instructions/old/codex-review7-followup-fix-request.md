# P0: リリース阻止項目

## 2. 実E2Eを必ず本走する

Playwrightのテスト収集成功は、動作成功を意味しません。

次の一連の操作を、実際に起動したアプリとMariaDBに対して実行してください。

```text
ログイン
→ プロジェクトを開く
→ テストを新規作成
→ 確認項目を5件作成
→ テスト全体を保存
→ テスト実行を作成
→ 対象テストを選択
→ 実行開始
→ 5件を順番に結果保存
→ 不合格ケースへ実績結果を入力
→ 証跡ファイルを登録
→ クリップボード画像を登録
→ 実行完了
→ 完了後に結果変更
→ 完了後に証跡追加
→ ログアウト
→ 再読み込み
→ 保護APIが401
```

### 必須確認

- 結果を変更しても元の状態へ戻らない
- 「保存して次へ」を連続使用できる
- 古い保存レスポンスが最新入力を上書きしない
- 証跡追加後に画面とDBが一致する
- 完了後更新者・更新日時が即時表示される
- ログアウト後、戻る・更新でも認証済み画面に戻らない

資格情報や対象プロジェクトが不足する場合は、テスト用データを自動作成してください。環境不足を理由にE2E本走を省略しないでください。

## 3. テスト実行作成・開始エラーの原因を実証する

ユーザー環境では「テスト実行ができない」事象が確認されています。

以下を実際に検証してください。

- 新規実行フォームでテストを選択
- 実行名、環境、ビルド、担当者を入力
- 実行作成
- 実行開始
- ケーススナップショット生成
- 結果入力画面表示

APIレスポンス、DBレコード、監査ログを確認し、どの段階まで成功したかを記録してください。

エラーが再現しない場合も、テスト結果とDB確認内容を記録してください。

---

## 4. 結果保存の競合試験

保存要求に連番管理を追加しただけで完了としないでください。

次を自動テストしてください。

1. 保存中に同じケースへ追加入力
2. 先のリクエストを意図的に遅延
3. 後のリクエストを先に成功
4. 古いレスポンスが返る
5. 最新入力が保持される

また、ケース切り替え、証跡追加、親コンポーネント再取得の最中でも入力が戻らないことを確認してください。

---

## 5. ログアウトを実セッションまで検証

共通ログアウト関数の追加だけでは不十分です。

### 必須動作

- サーバー側セッション破棄
- Cookie無効化
- クライアント状態破棄
- ログイン画面へ遷移
- ログアウト後の`GET /api/auth/me`が401
- ブラウザ再読み込み後も401
- 戻る操作で保護画面を再利用しない

### API失敗時

ログアウトAPIが失敗した場合、単にローカル状態だけを消して成功扱いにしないでください。

利用者へ次の趣旨を表示してください。

```text
画面上のログイン状態は解除しましたが、
サーバーとの通信に失敗したためセッションを完全に終了できない可能性があります。
ブラウザを閉じるか、再度ログアウトしてください。
```

サーバーセッションが残った状態で画面更新すると再認証される可能性をE2Eで検証してください。

# P1: 仕様・データ整合性

## 6. 完了後更新情報を即時反映

完了済み実行の結果または証跡を変更した場合、次を同一操作後に画面へ即時反映してください。

```text
post_completion_updated_at
post_completion_updated_by
test_runs.version
```

画面再読み込みや実行再選択を要求しないでください。

推奨方法:

- ケース結果更新APIのレスポンスに更新後の実行情報を含める
- 証跡追加APIのレスポンスに更新後の実行情報を含める
- 返却値で親stateを更新する

完了後変更時の監査ログも確認してください。

---

## 7. 完了後編集範囲を仕様として確定

現在、結果と証跡は完了後編集できても、以下は編集できない可能性があります。

- 実行名
- 環境
- ビルド
- 実行メモ
- 実行担当者
- シナリオ担当者
- 実行日時
- ケース追加・除外
- シナリオ追加・除外
- 元定義の再取得

確定仕様と照合し、次のどちらかを明文化してください。

### 方針A

完了後は結果・実績・備考・証跡のみ編集可能

### 方針B

確定仕様に記載された範囲まで完了後編集可能

コード、API、UI、監査ログ、権限テストを同じ方針へ統一してください。

---

## 8. 見る場所画像のライフサイクル管理

見る場所画像をファイル保存へ移行した後も、関連解除されたファイルが残る可能性があります。

次を実装してください。

### 一時アップロード

- アップロード直後は一時状態
- テスト全体保存時に正式関連付け
- 保存されなかった一時ファイルは一定時間後に削除

### 関連解除

ケースから画像を削除した場合、以下を判定してください。

- 他の現行ケースが参照しているか
- 過去実行スナップショットが参照しているか
- 監査・履歴保持対象か

参照がなければDBレコードと実ファイルを削除してください。

参照がある場合は削除せず、関連のみ解除してください。

### 定期クリーンアップ

未関連・期限切れファイルを削除するジョブを追加してください。

削除件数、失敗件数、対象IDをログへ記録してください。

---

## 9. 画像ファイルの実体検証

クライアントが送信したMIMEタイプと拡張子を信用しないでください。

以下を実装してください。

- 画像デコーダで実体を解析
- 壊れた画像を拒否
- 許可形式を明示
- SVGは拒否または安全なPNGへ変換
- Content-Typeは解析結果から決定
- ファイル名をレスポンスヘッダーへ直接展開する場合は安全にエスケープ
- 画像処理失敗時に一時ファイルとディレクトリを削除

許可形式の例:

```text
PNG
JPEG
WebP
GIF
```

業務要件でTIFF等が必要な場合は、仕様へ追加してください。

---

## 10. 実行version同期

完了後ケース結果や証跡更新で`test_runs.version`を増加させる場合、フロントの実行stateも同時に更新してください。

古いversionのまま次のPATCHを送って409になる状態を防止してください。

409時は、単にエラー表示するだけでなく次を選べるようにしてください。

```text
最新状態を再読み込み
現在の入力をコピーして保持
差分を確認
```

---

## 11. シナリオ結果の自動集計を固定

シナリオ結果はケース結果からの自動集計専用としてください。

旧UI、旧API、非表示コンポーネントを含めて、シナリオ結果を利用者が直接更新する経路を削除してください。

集計ルールをテストしてください。

例:

```text
未実行が1件以上 → 未完了
ブロックが1件以上 → ブロック
不合格が1件以上 → 不合格
すべてスキップ → スキップ
すべて合格 → 合格
```

実際の優先順位は確定仕様に合わせてください。

# P1: テスト構成

## 12. E2Eを分割

単一の巨大E2Eだけに依存しないでください。

最低限、次へ分割してください。

```text
auth.spec.ts
test-design.spec.ts
run-create-start.spec.ts
run-result-save.spec.ts
evidence.spec.ts
run-completion.spec.ts
post-completion-edit.spec.ts
user-project-assignment.spec.ts
migration-schema.spec.ts
```

各テストは独立して実行できるようにし、テストデータの作成とクリーンアップを行ってください。

失敗時は以下を保存してください。

- スクリーンショット
- 動画
- trace
- APIレスポンス
- 関連するサーバーログのrequest ID

---

## 13. E2Eをskipしない

環境変数がない場合にテストをskipしないでください。

必要な認証情報、管理者、プロジェクト、初期データはテストセットアップで作成するか、明確な設定不足としてCIを失敗させてください。

「0件実行で成功」は禁止です。

# P2: 操作性改善

## 14. フォルダをエクスプローラー操作へ近づける

今回のリリース阻止修正に含まれていない以下を実施してください。

- 展開三角
- 選択行の明確なハイライト
- 右クリックメニュー
- F2またはインライン名前変更
- Enterで開く
- Deleteで削除
- Escで編集取消
- ドラッグ中の移動先ハイライト
- 自分自身・子孫への移動禁止
- パンくず
- 複数選択
- 複数移動
- キーボード操作
- フォルダ作成時のインライン入力

`window.prompt`を通常操作に使用しないでください。

## 15. アップロード上限の表示を正確にする

画面へ「無制限」と表示しないでください。

実際には次の制限を受けます。

- Fastify bodyLimit
- multipart設定
- リバースプロキシ
- OpenShift Route
- ストレージ容量
- ブラウザ
- タイムアウト

アプリ独自上限を設けない方針でも、実環境上限を取得または設定値から表示してください。
