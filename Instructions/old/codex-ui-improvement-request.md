# ザ・テスト Web版 UI・導線改善 実装依頼

## 目的

添付HTMLと既存ソースを確認し、専門のQA担当者だけでなく、開発者・運用担当者・業務担当者も迷わず使えるUIへ再設計してください。

参考モックアップ：`the-test-ui-improvement-mockup.html`

既存のDB構造やAPI名称をそのまま画面へ露出させるのではなく、利用者の目的である以下の流れを中心にしてください。

```text
テストを設計する
→ テストを実行する
→ 結果と証跡を残す
→ 完了する
```

---

## 1. テスト設計画面

### 現状の問題

- 「新規作成」「既存編集」が別モードで、既存シナリオの編集には追加の読み込み操作が必要
- 「シナリオの手順」と表示されているが、実際は1行ごとにテストケースを作るため意味が曖昧
- ケース、シナリオ、データセット、フォルダから作成などの選択肢が同時に表示され、初心者には複雑
- ケース詳細を別画面へ移動して編集するため、編集の流れが分断される
- フォルダUIがエクスプローラーのように直感的ではない

### 変更後

3ペイン構成を基本としてください。

#### 左ペイン：テスト一覧

- シナリオを画面上では「テスト」と表示
- 検索
- フォルダツリー
- 新規作成
- 選択中テストの明確なハイライト
- クリック時に中央へ即時読み込み
- 右クリックまたは `…` メニュー
  - 複製
  - 名前変更
  - 移動
  - 削除
  - テスト実行を開始
- フォルダの作成、名前変更、移動、ドラッグ＆ドロップ
- 自分自身または子孫への移動は禁止
- 未保存状態で別テストへ移動するときだけ確認

#### 中央：確認項目の一括編集

- 新規と既存で同じエディターを使用
- 「1行＝1確認項目」であることを明示
- 列：
  - No.
  - 確認項目名
  - 操作
  - 期待結果
  - テストデータ
  - 操作
- Excelから複数セル貼り付け
- 行追加、削除、複製、上下移動
- セル内容に応じて高さを自動拡張
- 横スクロールに頼りすぎず、入力内容を常に確認可能にする
- 既存テストからコピー
- Excelから取り込み
- 共通テストデータは折りたたみ式の任意設定

#### 右ペイン：選択中の確認項目詳細

- 前提条件
- 目的
- 優先度
- タグ
- フォルダ
- 複数操作手順
- 見る場所
- 画像追加
- クリップボード貼り付け
- 個別テストデータ

表には概要を表示し、詳細項目を右ペインへ分離して表の横幅を抑えてください。

### 保存

- 「シナリオを保存」ではなく「テスト全体を保存」
- 保存対象：
  - シナリオ
  - ケース
  - 手順
  - テストデータ
  - フォルダ関連
- 一括トランザクションで保存するAPIを用意
- 途中失敗時にケースだけ残る状態を作らない
- 保存状態を常時表示
  - 未保存
  - 保存中
  - 保存済み時刻
  - 保存失敗
- 保存後に「テスト実行へ」ボタンを表示

## 2. テスト実行画面

### 現状の問題

- 実行情報、改訂、シナリオ結果、ケース結果、証跡が同じ画面に並び、次に行う操作が分かりにくい
- 結果を変更しても初期状態へ戻る不具合がある
- 証跡追加時にサーバー内部エラーが表示される
- APIエラーが利用者向けに整理されていない

### 変更後

実行準備と結果入力を分けてください。

#### 実行準備

- 実行名
- 対象テスト
- 環境
- ビルド
- 担当者
- 予定日時
- メモ
- 「実行を開始」

#### 実行中

左側に確認項目一覧、右側に現在の確認項目を表示します。

- 進捗 `2 / 5`
- 前へ／次へ
- 結果：
  - 未実行
  - 合格
  - 不合格
  - ブロック
  - スキップ
- 実績結果
- 備考
- 実行日時
- 証跡
- 「保存して次へ」
- 最後に「テストを完了」

### 不具合修正

- 結果変更後に初期状態へ上書きされないこと
- 自動保存の競合や古いレスポンスで最新入力を上書きしないこと
- 証跡をファイル選択とクリップボード貼り付けの両方から正常登録できること
- アップロード進捗、成功、失敗理由を証跡欄へ表示
- 技術的なサーバーエラー文をそのまま表示しない
- 画面には利用者向けメッセージとエラーIDを表示し、詳細はサーバーログへ記録

---

## 3. ユーザー管理

### 現状の問題

- ユーザーとプロジェクトの選択枠の幅・高さが異なる
- 割り当て後に解除できない
- どのユーザーがどのプロジェクトへ割り当てられているか把握しにくい

### 変更後

- 左右の選択枠を同じ幅・高さ・デザインに統一
- 先にユーザーを選択し、次にプロジェクトを選択
- 複数ユーザー × 複数プロジェクトを一括処理
- 明示的な確定ボタン：
  - 選択内容を割り当て
  - 選択内容を解除
- ユーザー一覧に割り当て済みプロジェクトを表示
- 割り当て／解除前に処理対象件数を表示
- 成功後に更新された割り当て状態を即時反映

---

## 4. ログアウト

- ログアウトボタン押下でサーバー側セッションを破棄
- Cookieを無効化
- ログイン画面へ遷移
- ブラウザ更新後に認証状態が復活しない
- ログアウト失敗時は利用者向けメッセージを表示

---

## 5. 用語

画面上では以下を基本としてください。

| 内部用語 | 画面表示 |
|---|---|
| scenario | テスト |
| test case | 確認項目 |
| test step | 操作手順 |
| expected | 期待結果 |
| data set | テストデータ |
| run | テスト実行 |
| evidence | 証跡 |
| procedure | 作業手順 |

管理者向け詳細画面や仕様書では内部名称を併記して構いません。

---

## 6. 受け入れ条件

### テスト設計

- 左側のテストを1回クリックすると中央へ内容が表示される
- 新規と既存が同じ表で編集できる
- 1行が何を表すか明確
- 入力文字がセル内で隠れない
- 複数行貼り付けができる
- ケース詳細を右ペインで編集できる
- フォルダをドラッグ＆ドロップで移動できる
- 一度の保存でテスト全体が整合性を保って保存される

### テスト実行

- 結果を選択後、別項目へ移動しても値が戻らない
- 画面更新後も保存済み結果が保持される
- 証跡ファイルとクリップボード画像を登録できる
- 保存中、保存済み、保存失敗が確認できる
- 1件ずつ前後へ移動しながら結果入力できる

### ユーザー管理

- ユーザーとプロジェクトの選択領域が同じサイズ
- 複数割り当てと複数解除ができる
- 現在の割り当て状況が確認できる

### ログアウト

- ログアウト後に保護APIへアクセスできない
- 戻る操作や更新でも認証済み画面を再表示しない

---

## 7. 実装時の注意

- 既存データを破壊しない
- 既存APIとの互換性を確認し、必要なら新APIへ段階移行
- 楽観ロックと監査ログを維持
- 権限検証を画面だけでなくAPIでも実施
- Markdownとアップロードファイルの安全対策を維持
- PC幅を主対象としつつ、狭い画面では3ペインを縦配置またはドロワー化
- Playwrightで主要導線のE2Eテストを追加
