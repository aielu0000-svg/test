あなたの考え方にかなり賛成です。

今の画面を見た限り、一番の問題は**「データの単位」が画面ごとにバラバラ**なことです。

* テストケースを作る
* シナリオを作る
* データセットを作る

と、それぞれ独立してしまっています。

でも実際にテスト設計する人は、

> **「ログイン機能のテストを作ろう」**

という考え方しかしません。

つまり利用者が考える単位は**シナリオ**なんです。

## ケースという概念を隠す

利用者は

「ケース作ります」

なんて考えません。

考えるのは

```
ログイン機能

↓

ログイン成功

↓

ログイン失敗

↓

権限なし
```

だけです。

なので

```
シナリオ

└ ケース
```

というDB構造はそのままで、

画面だけ

```
シナリオ編集

↓

Excel表

↓

保存

↓

裏でケース生成
```

にした方が圧倒的に分かりやすいです。

を画面下に置くだけ。

## 私ならタブも減らします

今

```
テストケース

一括編集

シナリオとデータ

テスト実行

手順書

Excel

入出力

ゴミ箱
```

ですが、

これなら

```
📋 シナリオ
　（作成・編集）

▶ テスト実行

📖 手順書

📥 インポート/エクスポート

🗑 ゴミ箱
```

くらいで十分です。

テストケースはシナリオ画面の内部機能として扱うので、独立タブにしない方が学習コストを下げられます。
